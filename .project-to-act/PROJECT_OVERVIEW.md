## 项目目标

- 从零重建编排层：LangGraph StateGraph 为**唯一执行路径**（废弃手写循环），设统筹 Agent（按工作流调度）、Worker Agent（执行）、审查 Agent（审查+Gate）三角色。
- 工具/技能先迁移、后逐个审查注册（五项 checklist + 台账）。
- 数据库（8 个 SQLite）与知识库、识别链、自进化包沿用旧仓库实现迁移；自进化补全三缺口（使用反馈接线、知识注入真实消费、红线周期检查）。
- 对外 API 与现有前端契约兼容（/runs、/runs/stream NDJSON、resume、上传）。
- 验收线：W913 订单 workflow 路径 m5.released **且** free 路径全链跑通（修复旧实现 `ingest_m5_planning_snapshot` 装配死点）。

## 范围

### 包含

- 编排层：路由决策、计划生成、工作流引擎（DAG 调度）、统一装配器、审查规则、Gate/resume、流式 API。
- 注册中心：115 个 manifest 工具合同 + 4 个本地识别工具 + 8 个技能的注册与绑定状态表。
- 资产迁移：contracts/registry/存储层/识别四件套/LLM 客户端/evolution 包/测试。
- 自进化接线与三缺口补全。

### 非目标

- 不重写工具业务实现（M0-M5 handler 业务语义不变）。
- 不改前端（他人开发，契约零改动）。
- 不改数据库 schema（8 库表结构沿用）。
- 不做 M7 法务/M8 非标等新业务功能（其工具合入 main 后走注册流程进 v2）。
- **M6 财务口径变更（2026-09-13 ~ 09-14，D-005~D-011）**：原"不做 M6"改为**在 v2 直接开发 M6**（F-008，分支 `feat/m6-finance-20260913`）；M6 写操作按**三段式（先批准、再落库）**；该条文**只约束 M6**（D-010），存量 M0-M5 写工具维持既有"执行后开门"语义、不计为设计债（B-014 据此改标）；M6 的 Skill 面按**算/记两个 Skill 划分**且**默认操作必为纯读**（D-011）。

## 技术路线与关键约束

- FastAPI + LangGraph（StateGraph + interrupt() + SqliteSaver checkpointer）。
- LLM：本地 Qwen（GB10 35B 生产默认 / 本机 27B 联调，OpenAI-compatible 单一配置源）；DeepSeek 仅限授权的进化任务（沿用旧仓库 D-012）。
- 资产复制自 `yunpai-39092-repo@9c7c799`（github/main）+ 主工作区未提交的 evolution 包（与 `github/feat/evolution-20260908` 同源）。
- 设计原则：唯一执行路径 / 装配单源 / 合同驱动审查 / 语义自由非事实自由 / 路由目录只含已绑定工具 / API 契约兼容。

## 数据与安全边界

- 数据分类：业务数据（订单/BOM/SOP/工程图/库存）仅存 runtime SQLite 与受控目录；运行库/演进库/候选库分离。
- 敏感信息（身份证/银行卡/工资）脱敏后才入库；原始敏感文件不进任何 git。
- 大文件（*.sqlite、*.tar.gz、*.zip、*.log、备份目录）不进 git。
